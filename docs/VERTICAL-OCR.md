# 竖排（右起）扫描古籍的识别路线

横排流水线对竖排扫描本会失败：检测模型给出的框在竖栏上碎裂，文字层则常是「逐列乱序」的假象
（有字、字数正常，拼出来读不通）。本仓库另有一条**独立的竖排分支**，只处理「竖排右起、单栏多列」
的线装/影印扫描本，横排流程与 12 项门禁判据一行不变。

## 路线（不用检测框、不旋转页面）

```
PDF 单页 → 灰度 → 全列宽墨迹投影 → 自相关估列距（pitch）
        → 每条列距窗口取墨谷作列边界 → 列内按墨量阈值切字（tall_thr165）
        → 每 10 字直立横拼成一行（cell 44×52，缩略 38×40）
        → PP-OCRv5 rec（mobile，仅识别器，不含检测器）
        → 单字笔画校正 → 标点归一 → 按列右→左拼成整页文本
```

- **不旋转原页**：切字与拼图都在原分辨率灰度上做，避免插值糊笔。
- **只用 rec**：竖排的难点在「分列 + 列内切字」，检测模型在这里是负资产。
- **异体归一口径**：正俗体（裏/里、煙/烟、爲/為…）在校对与 CER 统计时按表归一，
  语义不同的字（鐘/鍾）不归一。

实测两页基线（1800×2558 级扫描页）：原始 CER 1.82% / 2.97%，异体归一后 **0.40% / 1.91%**，
标点偏差 0.0%，杂符 0，成本 1.2–1.5 s/页（整本约 13 分钟）。

## 页级去倾斜（2026-11-26 投产）

扫描本会出现**页级倾斜 1.5–2.0°**：斜切把列向墨迹投影糊平，自相关列距从 ~52px 崩到 ~18px，
真列被切成半字窄槽，识别器开始幻觉出整页乱码。竖排分支在外层加了一道「触发 → 找角 → 转正 → 结构校验」：

| 环节 | 做法 | 常量 |
|---|---|---|
| 前置 | 只处理正文页（`han ≥ 0.4×全书中位`），书影/封面/目录不碰 | `DESKW_HAN_RATIO` |
| 触发 A | 列距崩 **且** 栏数翻倍（`pitch < 0.8×中位` 且 `slots ≥ 1.6×中位`） | `DESKW_PITCH_RATIO` / `DESKW_SLOT_RATIO` |
| 触发 B | 2× 谐波列距（`pitch ≥ 1.8×中位`）——同页被切成双倍宽列 | `DESKW_HARMONIC_RATIO` |
| 找角 | ±3°、0.25° 网格扫投影方差，取局部极大为候选峰（最多 4 个） | `DESKW_LO/HI/STEP`、`DESKW_TOP_K` |
| 校验 | 转正后 pitch 须落回 `[0.8, 1.25]×中位`、`|slots−中位| ≤ 0.40×中位` | `DESKW_VERIFY_PITCH/SLOT` |
| 回退 | 首选峰校验失败 → 自动退次峰；全部失败 → **维持原结果**，只留尝试记录 | `choose_deskew_angle` |

方差曲线会被「假峰」骗（斜切状态下投影反而更整齐），因此**结构校验优先于方差**：
校验不过就退谐波候选，全不过就不动。这条纪律是实测出来的，不要简化掉。

## 缓存纪律（改动前必读）

| 键 | 组成 | 说明 |
|---|---|---|
| 基础键 | `sha1(pdf)+page+scale+PARAM_VERSION` | `PARAM_VERSION` 固定为 `vertical-ocr-v1`；递增 = 全书缓存作废重跑 |
| 变体键 | 同上 + `+deskew-v1` | 只有触发页写变体，与基础缓存互不覆盖 |

- 非触发页的输出与投产前**逐字节一致**（基础路径零改动）。
- 校验失败的页也会落一条「维持原结果 + 尝试记录」的变体缓存，避免重跑时反复搜索。
- 回退方式：删除所有 `*+deskew-v1.json` 即回到投产前行为。
- 竖排页级缓存放 `<book_dir>/.ocr_cache/`，整本重跑只补新页。

## 用法

```bash
export BOOKROOT=$PWD
# 模型在本仓库的 models/ 下（竖排分支专用，横排不需要）；tools/models/ 亦可（自动搜索先根后 tools），此 export 仅显式覆盖用
export VERTICAL_OCR_MODEL=models/ch_PP-OCRv5_rec_mobile.onnx

python tools/pipeline.py one "inbox/scan.pdf" --out books --title 书名 \
       --vertical --ear 书名,书名末三字
python tools/pipeline.py recheck "books/<书名>"
```

`--vertical` 只跑 convert 阶段：成段、卷章、页级闸由 `tools/vertical_book.py` 内建完成，
横排后处理阶段（bookfix/postfix/readability/…）不适用，`pipeline.py post` 会直接跳过。

## 竖排产物与页级闸

除 `book.json` 外另写 `竖排质检.json`：零字页、低字页、无句读页、抛错页逐页登记，分三级——

- **硬异常**：正文页极低字/无句读/抛错 → 必须复查；
- **观察**：可疑但未达硬标准；
- **参考**：前置页、原书空白页、卷首页（结构性低字，写明理由即可核销）。

页级闸只标异常，不静默通过；跨页/跨栏续接由「上栏末尾无句末标点」判定。

## 边界

- 双行夹注（正文大字 + 双行小字注混排在同一列）会被读成一行 → 属结构性缺口，靠页级闸标出后人工处理。
- 整页书影/图版页应判为 `figure`；识别器对无正文的图版页会输出乱码，`DESKW_HAN_RATIO` 前置只挡住去倾斜触发，不改变判定。
- 竖排分支与横排共用 `book.json` schema 与 12 项门禁，因此产物可直接进阅读器。
